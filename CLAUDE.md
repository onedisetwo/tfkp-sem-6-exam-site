# ТФКП Экзамен — инструкции для Claude Code

Сайт для подготовки к устному экзамену по ТФКП (мехмат МГУ, 6 семестр). Пользователь — Hasan, общаемся **по-русски**. История проекта и принятые решения: `docs/SUMMARY.md`.

## Роль

Ты опытный преподаватель ТФКП, который объясняет строго, но доступно, и готовит студента к устному экзамену. У студента минимальные знания предмета, 5 семестр он помнит плохо.

## Задание (исходная спецификация)

Экзамен устный: билет = 1 теоретический вопрос из программы, затем опрос по формулировкам и определениям, затем возможны задачи.

Сайт содержит:

1. **«База из 5 семестра»** (`00_base.md`) — только то, что нужно для билетов 6 семестра. Для каждого понятия: интуиция → строгое определение → простой пример → «где используется» (ссылки на билеты).
2. **Карта курса** (`01_map.md`) — какие билеты на что опираются и в каком порядке их учить.
3. **Страница на каждый билет** (`ticket_01.md` … `ticket_23.md`), единая структура:
   1. Краткий ответ на 1 минуту.
   2. Необходимые понятия со ссылками в базу.
   3. Определения и формулировки — точно, в обозначениях лектора.
   4. Доказательства: сначала «скелет» в 3–6 пунктах, затем полностью по шагам с пояснением «зачем мы это делаем».
   5. Интуиция и картинки (inline SVG).
   6. Пример или типовая задача с решением.
   7. Частые дополнительные вопросы экзаменатора с короткими ответами.
   8. Типичные ошибки и ловушки.
   9. Связи с другими билетами.
   10. Самопроверка: ответы скрыты в `<details>` (сейчас 10 вопросов на билет, в билетах 2–4 по 8).
4. **Сводка формул** (`02_formulas.md`), шпаргалка на одной странице.
5. **План подготовки** (`03_plan.md`) по дням с учётом зависимостей и днём повторения.

## Правила работы с источниками

- Все исходники лежат в `sources/`. Основной — `sem6_lecturer_notes_LaTex_human.pdf` (С6). Дополнительно `sem5_lecturer_notes_LaTex_human.pdf` (С5), программы `sem6_program.md` и `sem5_program.md`. Текст из PDF извлекается чисто: `pdftotext -layout файл.pdf -`.
- Определения и теоремы берём из лекций и **сохраняем обозначения лектора**.
- Если источники противоречат друг другу, используем лекции и ставим пометку **⚠️**. Нумерация ⚠️ 1–22 и [неразборчиво] 1–6 ведётся в `docs/analysis/03_discrepancies.md`.
- Нечитаемый фрагмент помечаем **[неразборчиво]**, не додумываем молча.
- Если вопроса билета нет в лекциях, даём стандартное изложение с пометкой **«нет в лекциях, стандартный вариант»** (div `::: nolect`). Целиком нет в С6: билеты 13, 14, 21, 22, 23; частично: 5–12, 16, 20.
- Перед правкой билетов 16–23 или формул прочитай `site/notes_16_23.md`. Таблица обозначений — `site/02_formulas.md#f-notation`. Новые соглашения записывай туда же, чтобы билеты не разъехались.

```
README.md, CLAUDE.md

sources/                      исходники (только читаем)
  sem5_program.md, sem6_program.md            программы (23 билета в 6 семестре)
  sem5_/sem6_lecturer_notes_LaTex_human.pdf   конспекты лекций
docs/

  analysis/                   разбор материалов (этап 1): понятия базы, карта, расхождения, структура;
                              живой файл — 03_discrepancies.md (реестр ⚠️), остальное — снимок 07.10
site/
  index.md            главная
  00_base.md          база, блоки A–F, якоря #A1 … #F8
  01_map.md           карта курса (SVG-граф и таблицы)
  02_formulas.md      сводка формул, раздел #f-notation
  03_plan.md          план подготовки
  04_overview.md      обзор курса: определения и формулировки по 6 темам
  ticket_NN.md        23 билета (образец структуры — ticket_05.md)
  notes_16_23.md      служебная страница с решениями по обозначениям (в меню её нет)
  style.css           оформление «Фокус», тёмная тема, печать
  site.js             меню, оглавление, тема, «выучено», навигация, таблица билетов
  fonts/              woff2: Onest, Source Serif 4, STIX Two Math
  build.sh            .md → .html (pandoc)
  bundle.py           весь сайт → ../tfkp_site.html (один файл, офлайн)
  check_site.py       проверка ссылок, якорей и ошибок MathML
```

HTML — генерируемые файлы, правим только `.md`, `style.css`, `site.js`.

## Сборка и проверка

```sh
sh site/build.sh             # pandoc X.md -s --mathml --css style.css -o X.html для всех страниц
python3 site/bundle.py       # пишет tfkp_site.html в корень
python3 site/check_site.py   # битые ссылки/якоря и <merror>; код выхода 1 при ошибках
```

Деплой: при push в `main` workflow `.github/workflows/pages.yml` делает то же самое (pandoc 3.1.3) и публикует `tfkp_site.html` как `index.html` на GitHub Pages. Ошибка `check_site.py` останавливает деплой.

Нужен pandoc (проверено на 3.1.3). После **любой** правки: пересобрать затронутые страницы, пересобрать `tfkp_site.html`, прогнать `check_site.py`. При изменении вёрстки дополнительно проверь страницу на ширине 390px (телефон) и в тёмной теме, например через Playwright.

## Соглашения в Markdown

- Каждый `.md` начинается с YAML (`title`, `subtitle`, `lang: ru`), затем `<script src="site.js"></script>` и `<noscript>` со ссылками. Меню рисует `site.js`, в Markdown его нет.
- **Статус страниц хранится только в `site.js`**: массив `TICKETS` (поля `status`: ready/soon/wait, `cover`: ok/part/miss) и `READY_PAGES`. Новая страница видна в меню только после того, как её отметили там.
- Формулы: только `$…$` и `$$…$$`, стандартный LaTeX, понятный pandoc с `--mathml`. **Без `\newcommand`**, макросы раскрываем. Вместо `align` используем `aligned` внутри `$$`.
- Ссылки между файлами: `[Билет 5](ticket_05.html)`, в базу: `[C3](00_base.html#C3)`.
- Скрытые ответы: `<details><summary>Ответ</summary>` … `</details>`, с пустыми строками вокруг содержимого, чтобы pandoc разбирал Markdown и формулы внутри.
- Плашки (fenced divs): `::: short` (краткий ответ), `warn` (⚠️), `nolect` (нет в лекциях), `idea`, `example`, `used` (где используется), `skeleton`, `concept`, `quiz` (самопроверка), `drill` (типичные вопросы и задачи в базе), `tiles` (плитки на главной), `key` (ключевое понятие в обзоре), `aside` (серая справка). Span `[→ Б12]{.where}` — мелкая серая подпись «где используется». Стили для них в `style.css`.
- SVG рисуем inline, цвета через `currentColor` и CSS-переменные, чтобы схемы читались в тёмной теме и при печати.
- **Ловушка pandoc:** строка ответа, начинающаяся с `(1) `, превращается во вложенный список. Экранируй: `\(1)`.

## Дизайн

Концепция «Фокус» (выбор Hasan). Секция «Оформление «Фокус»» в `style.css` стоит **перед** правилами печати специально, чтобы печать её перекрывала. Шрифты: Onest (заголовки и интерфейс), Source Serif 4 (текст), STIX Two Math (MathML), все локально в `site/fonts/` по относительным путям, сайт работает без интернета. Тёмная полоса меню на всю ширину, колонка текста 46rem. На экранах ≥1180px у страниц с оглавлением оно закреплено слева (`body:has(> nav.page-toc)`).

`bundle.py` подменяет куски `site.js` регулярками (`currentFile`, запуск `init`). Если меняешь эти места в `site.js`, поправь и `bundle.py`, иначе он упадёт с assert.

## Как работать с Hasan

- Работаем поэтапно: Hasan говорит, какой этап или порцию делать. Не делай всё за один ответ.
- Перед крупными изменениями внешнего вида предложи несколько вариантов на выбор.
- Ответы короткие, по делу, с указанием, что проверено.
